Agent Screen Studio

AGENT SCREEN STUDIO01 / 06
The Problem

Every agent needs structured input. Hand-building those forms doesn’t scale.

AI agents need topics, URLs, settings, and files. Building a bespoke form for each one is slow, inconsistent, and easy to get wrong.

  • Proposes the screens an agent needs, with AI help.
  • Reviews — a human approves every field and layout block.
  • Publishes a clean, versioned experience in the browser.
  • Forwards collected answers to one or more real agent APIs.
Product / Ops

Describe an agent, approve the generated screens, publish a release.

Engineers

Attach endpoint URLs, auth, and scorecard contracts; export standalone frontends.

End users

Open a published agent link and complete a guided, branded journey.

AGENT SCREEN STUDIO03 / 06
Capabilities

What you can build

Up to 20 independently editable screens per agent project, single-screen or multi-step, wired to one or many agent backends.

Form screens

Validated fields — text, email, URL, file upload via data-url drop areas — owned by React JSON Schema Form.

Content screens

Welcome, instructions, and confirmation pages built from allowlisted blocks: headings, paragraphs, sections, dividers, callouts.

Branded presentation

Versioned display name, icon, accent color, welcome copy, submit label, and an optional wizard answer summary.

Multiple endpoints

One project can talk to several agent APIs. Creators choose how screens map to them:

  • One shared journey — fields for all endpoints collected across shared screens.
  • Separate screens per endpoint — each endpoint gets its own screen group, so a free-text topic never lands in a scrape url field.

On finish, enabled endpoints are called in order. In separate mode, each endpoint receives only values from its own screens.

Architecture

The manifest is the contract

One JSON manifest is shared by the LLM, the backend, and the frontend — and it passes three validation layers before it can be previewed or published.

Manifest contents

  • input_schema — JSON Schema of what to collect.
  • ui_hints.mode — single or wizard.
  • ui_hints.field_order — complete display order.
  • ui_hints.groups — wizard step definitions.
  • ui_hints.blocks — safe content and field placement.
1 · Safety

Rejects HTML, scripts, custom widgets, and identity metadata.

2 · Structural

Meta-schema enforces the audited field subset, 30-field max.

3 · Semantic

Constraints, refs, ordering, required fields, group ownership.

Guarantees & Scope

Deliberately strict, deliberately narrow

The product is opinionated about what it will not let you ship — and honest about what it is not.

What it guarantees

  • Humans approve every AI-suggested field and layout before it goes live.
  • No raw HTML, JavaScript, CSS, or JSON editing anywhere in the editor.
  • Secrets stay in server-side runtime auth — never in browser-visible config or exported ZIPs.
  • Releases are immutable and atomic; restoring never rewrites history.
  • Preview answers, credentials, and LLM reasoning are never persisted.

What it does not do

  • Run or host the customer’s agent logic.
  • Replace an agent-builder or pipeline platform.
  • Generate result dashboards from an agent’s output schema.
  • Embed a separate backend for every agent.
  • Bypass validation to ship unapproved screens.

It provides one shared backend for generation, validation, versioning, and retrieval — while keeping the generated UI generic and agent-independent.
